03

Navegación

routerLink y routerLinkActive

03
Navegación

routerLink

¿Qué hace?

  • Reemplaza el href en SPAs
  • Intercepta el click — sin recarga de página
  • Actualiza la URL en el browser
  • Renderiza el componente de la ruta

Sintaxis

// String simple <a routerLink="/books">Libros</a> // Array con parámetro <a [routerLink]="['/books', book.id]"> {{ book.title }} </a>

Importante: Importar RouterLink en el array imports del componente

03
Navegación

routerLinkActive

¿Qué hace?

  • Agrega una clase CSS cuando la ruta está activa
  • Ideal para resaltar el ítem activo en la navbar
  • Se aplica al elemento que tiene routerLink
<a routerLink="/books" routerLinkActive="active" [routerLinkActiveOptions]="{ exact: true }" > Libros </a>

exact: true

  • Sin exact: / queda activo en todas las rutas
  • Con exact: true: solo activo cuando el path coincide exactamente

Usar exact: true en la ruta raíz '/' para evitar que siempre esté activa

Parámetros de Ruta

Rutas dinámicas

localhost:4200 /books/ 42
path estático
:id — parámetro dinámico

Definición de la ruta

En app.routes.ts: path: 'books/:id'

El :id es el nombre del parámetro — puede ser cualquier nombre

Leer el parámetro

Usar ActivatedRoute inyectado en el componente para acceder al valor de :id

04
Parámetros de Ruta

ActivatedRoute

snapshot.params

// Lectura puntual (una sola vez) const id = this.route .snapshot.params['id'];

Útil cuando el componente se destruye y recrea al navegar

paramMap observable

// Reactivo — escucha cambios this.route.paramMap.subscribe( params => { const id = params.get('id'); } );

Útil cuando el componente se reutiliza y solo cambia el parámetro

En la mayoría de los casos, snapshot es suficiente. Usar el observable cuando el usuario navega entre instancias del mismo componente

Query Params

Filtros y estado en la URL

05
Query Params

Anatomía de la URL

localhost:4200 /books ? category = fiction & page = 1 #contact
path
query param key
query param value
fragmento / anchor

¿Cuándo usar query params?

  • Filtros (categoría, precio, stock)
  • Paginación (?page=2)
  • Búsqueda (?q=angular)
  • Estado que el usuario puede compartir/guardar

Leer query params

También via ActivatedRoute:

route.snapshot.queryParams['category'] // o reactivo: route.queryParamMap.subscribe(...)
05
Query Params

Fragmentos (Anchors)

localhost:4200 /books #reviews
path
fragmento / anchor

¿Para qué sirven?

  • Anclar a una sección dentro de la misma página
  • Deep-links a secciones (reviews, specs, comments)
  • Historial del navegador sin recargar
  • Accesibilidad: scroll automático al elemento

Navegar con fragmento

Con routerLink:

[routerLink]="['/books', id]" [fragment]="'reviews'"

O programático:

this.router.navigate( ['/books', id], { fragment: 'reviews' } );

Navegación Programática

Navegar desde TypeScript con el servicio Router

06
Navegación Programática

Router.navigate()

¿Cuándo usarlo?

  • Después de guardar un formulario
  • Redirect post-login
  • Navegación condicional (si hay errores, no navegar)
  • Cuando no hay un elemento de template para hacer click

Sintaxis

// Navegar a una ruta this.router.navigate(['/books']); // Con parámetro this.router.navigate(['/books', id]); // Con query params this.router.navigate(['/books'], { queryParams: { category: 'fiction' } });

Diferencia clave: routerLink es declarativo (template), Router.navigate() es imperativo (TypeScript). Usar el que corresponda al contexto.

07
Configuración

LocalStorage

¿Qué es?

  • API del browser para persistir datos en el cliente
  • Sobrevive recargas y cierre del browser
  • Almacena strings — se serializa con JSON
  • Scoped al dominio (no se comparte entre sitios)

No guardar datos sensibles — es accesible desde cualquier JS en la página

Casos de uso

Tokens de sesión

Recordar que el usuario está logueado

Preferencias

Tema, idioma, configuración de UI

Cache local

Evitar peticiones HTTP repetidas para datos que cambian poco

Módulos (Legacy)

NgModules — el patrón previo a standalone

¿Qué eran?

  • Clases con @NgModule que agrupaban componentes, directivas y pipes
  • declarations = piezas propias, exports = lo que se ve afuera
  • imports = otros módulos (FormsModule, HttpClientModule…)
  • Bootstrap con AppModule + bootstrapModule()

Legacy: standalone existe desde v14 y es default desde v17. @NgModule sigue funcionando pero no se recomienda para proyectos nuevos.

¿Para qué se usaban?

Encapsulación

Scope de compilación: qué piezas podía usar cada template

Routing por feature

RouterModule.forChild() en cada módulo, forRoot() en la raíz

Lazy loading

Unidad de carga diferida: un .module.ts por chunk

SharedModule

Re-exportar piezas comunes para no repetir imports

📦
Módulos (Legacy)

De AppModule a standalone

Estilo clásico — app.module.ts

// Angular < 14 import { NgModule } from '@angular/core'; import { BrowserModule } from '@angular/platform-browser'; import { RouterModule } from '@angular/router'; @NgModule({ declarations: [AppComponent, BookListComponent], imports: [BrowserModule, RouterModule.forRoot(routes)], providers: [BookService], bootstrap: [AppComponent] }) export class AppModule {}

Equivalente moderno

  • declarations → desaparece — cada componente trae su propio imports
  • providers globales → app.config.ts (ApplicationConfig)
  • RouterModule.forRoot(routes) → provideRouter(routes)
  • HttpClientModule → provideHttpClient()
  • bootstrap: [AppComponent] → bootstrapApplication(AppComponent, appConfig) en main.ts

¿Cuándo me lo voy a cruzar? Proyectos legacy, librerías de terceros que aún exportan módulos (se pueden importar desde un componente standalone) y tutoriales de Angular ≤ 13.
