01
REST & HTTP

Verbos HTTP — un verbo, una intención

REST (Representational State Transfer) — convención para diseñar APIs donde cada URL es un recurso y cada verbo HTTP es una acción.

Verbo Acción Ejemplo
GETObtener un recursoGET /books
POSTCrear un recursoPOST /books
PUTReemplazar el recurso completoPUT /books/3
PATCHActualizar parcialmentePATCH /books/3
DELETEEliminar un recursoDELETE /books/3

Idempotencia: GET, PUT, DELETE devuelven el mismo resultado si se ejecutan varias veces. POST y PATCH pueden no serlo.

01
REST & HTTP

Status codes — la respuesta de un vistazo

2xx — Éxito

  • 200 OK — request exitosa
  • 201 Created — recurso creado
  • 204 No Content — éxito sin body

4xx — Cliente

  • 400 Bad Request
  • 401 Unauthorized — falta auth
  • 403 Forbidden — no tiene permiso
  • 404 Not Found

5xx — Servidor

  • 500 Internal Server Error
  • 502 Bad Gateway
  • 503 Service Unavailable

Regla mental: 4xx → vos hiciste algo mal (request). 5xx → el servidor rompió. 2xx → todo bien.

HttpClient

El cliente HTTP de Angular — observable-first

03
HttpClient

provideHttpClient() — el setup moderno

Desde Angular 15+, se habilita HTTP en app.config.ts con provideHttpClient() — la forma estándar en proyectos standalone.

// app.config.ts import { provideHttpClient, withFetch } from '@angular/common/http'; export const appConfig: ApplicationConfig = { providers: [ provideRouter(routes), provideHttpClient(withFetch()), // usa la Fetch API nativa (recomendado) ], };

withFetch() reemplaza el viejo XMLHttpRequest con la Fetch API nativa — mejor tree-shaking, soporta SSR & streaming.

📦
HttpClient (Legacy)

HttpClientModule — solo para reconocer

Estilo NgModule (pre-v15)

// app.module.ts — NO usar en proyectos nuevos import { HttpClientModule } from '@angular/common/http'; @NgModule({ imports: [BrowserModule, HttpClientModule], }) export class AppModule {}

¿Por qué saberlo?

  • Proyectos legacy y tutoriales viejos lo usan
  • Eliminado en Angular 18+
  • Reemplazo directo: provideHttpClient()
  • Equivalencias: HttpClientJsonpModule → withJsonpSupport(); HTTP_INTERCEPTORS → withInterceptors([...])

Criterio: usar provideHttpClient() siempre — reconocer HttpClientModule en código ajeno.

03
HttpClient

GET tipado en un servicio

Inyectar HttpClient con inject() y tipar la respuesta vía el generic <T> — el observable emite el body ya parseado.

import { HttpClient } from '@angular/common/http'; import { inject } from '@angular/core'; @Injectable({ providedIn: 'root' }) export class BookService { private http = inject(HttpClient); private apiUrl = inject(API_URL); // InjectionToken con el endpoint getBooks(): Observable<Book[]> { return this.http.get<Book[]>(this.apiUrl); } getBookById(id: number): Observable<Book> { return this.http.get<Book>(`${this.apiUrl}/${id}`); } }
03
HttpClient

POST / PUT / PATCH / DELETE

createBook(book: Partial<Book>): Observable<Book> { return this.http.post<Book>(this.apiUrl, book); } updateBook(id: number, book: Partial<Book>): Observable<Book> { return this.http.put<Book>(`${this.apiUrl}/${id}`, book); } patchBook(id: number, patch: Partial<Book>): Observable<Book> { return this.http.patch<Book>(`${this.apiUrl}/${id}`, patch); } deleteBook(id: number): Observable<void> { return this.http.delete<void>(`${this.apiUrl}/${id}`); }

Lazy: ninguno de estos métodos dispara el request hasta que alguien hace .subscribe() (o el template usa | async).

Manejo de errores con catchError

En el servicio

import { catchError, throwError } from 'rxjs'; getBooks(): Observable<Book[]> { return this.http.get<Book[]>(this.apiUrl).pipe( catchError(err => { console.error('Error:', err.status); return throwError(() => new Error('No se pudo cargar') ); }) ); }

En el componente — observer object

this.bookService.getBooks() .subscribe({ next: (books) => this.books = books, error: (err) => this.errorMessage = err.message, complete: () => this.isLoading = false, });

subscribe(cb, errCb) con 2 args está deprecado en RxJS 7+ — siempre usar el observer object.

Consumir Observables en el template

async pipe + cleanup automático

04
async pipe

El async pipe — sin subscribe manual

Se suscribe al observable, entrega el valor al template y cancela la subscripción cuando el componente se destruye. Cero memory leaks.

Componente

import { AsyncPipe } from '@angular/common'; @Component({ imports: [AsyncPipe], ... }) export class BookListComponent { books$ = this.bookService.getBooks(); // Observable, SIN subscribe }

Template

@if (books$ | async; as books) { @for (book of books; track book.id) { <app-book [book]="book" /> } } @else { <p>Cargando...</p> }
04
async pipe

takeUntilDestroyed() — cuando necesitás subscribe

A veces no podés usar el async pipe (ej: side effects, lógica imperativa). takeUntilDestroyed() cancela el observable cuando el componente se destruye — sin ngOnDestroy.

import { takeUntilDestroyed } from '@angular/core/rxjs-interop'; export class BookListComponent { books: Book[] = []; constructor() { // se cancela automáticamente al destruir el componente this.bookService.getBooks() .pipe(takeUntilDestroyed()) .subscribe({ next: b => this.books = b }); } } // Fuera del constructor: pasar DestroyRef explícito private destroyRef = inject(DestroyRef); ngOnInit() { this.books$.pipe(takeUntilDestroyed(this.destroyRef)).subscribe(...); }

RxJS — operadores prácticos

Transformar, combinar y observar streams

05
RxJS

map & tap

map — transformar

getBookTitles(): Observable<string[]> { return this.http .get<Book[]>(this.apiUrl) .pipe( map(books => books.map(b => b.title) ) ); }

Cambia el valor que emite el observable, no el stream en sí.

tap — side effects sin tocar el valor

this.books$.pipe( tap(books => console.log('books:', books) ) ).subscribe(...);

Útil para debugging, logging o triggers laterales (analytics, toast). El stream sigue intacto.

05
RxJS

switchMap & forkJoin

switchMap — cancelar lo previo

searchTerm$.pipe( switchMap(term => this.bookService.search(term) ) ).subscribe(r => this.results = r);

Ideal para autocompletes & búsquedas: si el usuario tipea de nuevo, el request anterior se descarta.

forkJoin — en paralelo

forkJoin({ books: this.bookSvc.getBooks(), cats: this.catSvc.getCategories(), }).subscribe({ next: ({ books, cats }) => { this.books = books; this.cats = cats; } });

Lanza todos a la vez y espera que todos completen. Cae si alguno falla.

06
Pipes

Pipes built-in — los más usados

Pipe Para qué Ejemplo
currencyFormato monetario{{ price | currency:'ARS' }}
dateFormato de fecha{{ d | date:'dd/MM/yyyy' }}
uppercase / lowercaseCambio de caja{{ text | uppercase }}
jsonSerializar (debug){{ data | json }}
sliceCortar string o array{{ list | slice:0:5 }}
asyncSuscribir a un Observable{{ obs$ | async }}

Pipes son funciones puras: dada la misma entrada, devuelven la misma salida. Angular las cachea — no se recalculan si el input no cambió.

06
Pipes

Custom pipe — TruncatePipe

Definirlo

// pipes/truncate.pipe.ts import { Pipe, PipeTransform } from '@angular/core'; @Pipe({ name: 'truncate', standalone: true }) export class TruncatePipe implements PipeTransform { transform( value: string, limit = 50 ): string { return value.length > limit ? value.slice(0, limit) + '...' : value; } }

Usarlo

// book-card.component.ts @Component({ imports: [TruncatePipe], template: ` <h3>{{ book.title | truncate:30 }}</h3> <p>{{ book.desc | truncate }}</p> ` })

standalone: true + agregar en el imports del componente. Sin declarations, sin módulos.
